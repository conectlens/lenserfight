Three new MCP tools complete thread CRUD parity for replies, mirroring the existing
confirm-gated delete pattern used by `delete_thread`:

- `add_thread_reply` — post a reply to any thread visible to the caller (`fn_create_thread_reply`)
- `list_thread_replies` — read a thread's reply tree, oldest first (`fn_get_thread_replies_page`)
- `delete_thread_reply` — delete a reply the caller authored, requires `confirm: true` (`fn_delete_thread_reply`)

All wire to existing Supabase RPCs — no new database functions. Separately, a new
`.github/workflows/deploy-mcp-server.yml` job replaces the previous manual `wrangler deploy`
process: it uses `nx show projects --affected` to redeploy the Worker automatically whenever
a push to `main` touches `apps/mcp-server` or a shared lib it depends on.
