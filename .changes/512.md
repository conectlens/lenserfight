Deleting a thread resolves it first so ownership can be checked, and that lookup only
reaches private or draft threads when it is given a viewer id — its fast path reads the
public threads view, and the slow path returns nothing without a viewer. The profile page
passed only the handle, so an owner's own unpublished thread appeared not to exist. The
thread detail page already passed the viewer id, which is why the same delete worked
there.

The viewer id was also declared optional, and that optionality is the underlying defect:
it let a caller omit a value the function cannot work without and still compile. It is
now required, so the same mistake becomes a compile error rather than a runtime failure
reported as a missing thread. Both existing callers already supplied it.
