`workflowsService.startRun` gained an `executor` parameter and forwards it to the
repository, but the spec still asserted the five-argument call, so both `startRun`
assertions failed with an unexpected sixth `undefined`.

Both assertions move to the current arity, and a third test covers the parameter itself,
which had none. That gap was worth closing rather than only silencing the failure:
`executor` decides whether a run is claimable by the background worker or driven by the
browser, so a silent failure to forward it would strand runs — the exact condition the
change that introduced it set out to fix — with no test noticing.
