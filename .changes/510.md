Each lifecycle menu ran its own status query keyed by artifact id, so a list paid one
round-trip per row.

The new batch endpoint returns up to 200 artifacts of one type in a single call, keyed by
id. It loops over the existing single-artifact function rather than reimplementing it as
a set query, because that function owns both the visibility check and the per-type
response shape; a second implementation could drift from the original and turn the batch
path into an information leak. The saving being pursued is the round-trip, not the
per-artifact query. An artifact the caller cannot see is omitted instead of failing the
whole batch, so one hidden row cannot blank a page of badges.

Statuses are handed to each menu as a prop rather than seeded into the query cache. The
two race: menus mount and issue their queries in the same render pass that starts the
batch, so a cache write arriving after the batch resolves is already too late to prevent
the individual requests.

The endpoint caps its input so one request cannot become unbounded work, and the client
splits longer id lists across calls, since lists that page in more results legitimately
exceed that cap.
