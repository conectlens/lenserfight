`apps/worker` had never built successfully in this repo: dead Nx-scaffold `.tsx` stub
files shadowed the real barrel modules they sat beside (esbuild silently resolved
`./lib/validation` etc. to the wrong file), `strict` mode was never set in the worker's
tsconfig chain (causing bad discriminated-union narrowing), `import.meta.env` (Vite-only)
leaked into several shared libs the worker pulls in transitively with no Node-safe
fallback, and an incidental unused browser Supabase client — instantiated only as a side
effect of a barrel import — crashed at startup trying to read `document.cookie` in Node.

Separately, `battles.execution_configs` (the table the real worker execution path reads
a contender's provider/model from) had broken RLS (comparing `creator_lenser_id` directly
to `auth.uid()`, mismatched id spaces) and no RPC to write to it at all, so no battle
could ever have had a model configured through the intended pipeline. `fn_battles_get_public`
never included `'executing'` in its status whitelist, so any running battle was invisible
to its own creator.

Also fixes the generative-media battle-execution branch to resolve and inject an
`ai_agent` contender's `personality_note` the same way the text branch already did — image/
audio/video battles previously ran every agent with zero character reflection.
