`pnpm audit --prod --audit-level high` resolves advisories against npm's database at run
time rather than against anything committed here, so a newly published advisory can turn
the gate red on an unchanged lockfile. That is what happened: the job passed on
`development` and `main` earlier the same evening and then failed on all branches with no
dependency change behind it.

The two affected packages needed opposite treatment. Every `nanoid` consumer in the tree
already resolved inside 3.x, so a floor of `>=3.3.17 <4` clears both of its advisories as
a patch lift with no API surface change. `image-size` has no such option — its only
patched release is a breaking major that `metro@0.83.3` does not support, and its
exposure is limited to build-time image parsing, so it is recorded as an accepted risk
with an exit condition instead of being forced.

Both settings live in `pnpm-workspace.yaml`. pnpm 11 no longer reads the `pnpm` field in
`package.json` and drops it with only a warning, which would have made a security floor
placed there a silent no-op.
