An upload's storage path has to match exactly across three steps: requesting the signed
URL, the path carried inside the signing token, and the upload itself. A path built
straight from the original filename survives some of those steps escaped and others raw,
so the signature stops matching and the upload is rejected. The signing step still
succeeded, which is why the failure gave no hint that the filename was responsible, and
it left a half-created media record behind.

Thread uploads built the path directly from the filename. They now normalise it first.

The lens attachment path already did this correctly, so its helper moved to the shared
text utilities and both features use it, rather than a second copy of the same rules
being introduced. The shared version additionally normalises the file extension instead
of only lowercasing it, removes any directory prefix so a path cannot gain an unexpected
separator, and treats a leading dot as part of the name rather than an extension marker.
